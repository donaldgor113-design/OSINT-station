## Правила синхронізації

1. **Нова ідея** → додається в секцію «Активні ідеї» зі статусом `🔵 заплановано`
2. **Ідея в роботі** → статус `🟡 в роботі`
3. **Ідея реалізована** → статус `✅ виконано`, дублюється в PROGRESS.md, тут лишається як історія
4. **Ідея відхилена** → статус `❌ відхилено` з причиною
5. **Не дублювати:** якщо щось вуже є в PROGRESS.md — тут не повторюємо, лише посилаємось

## Активні ідеї

### 🔵 Патерн master-detail для всіх вкладок (ТЗ по UI/UX)

**Ідея:** усі вкладки будуються на одному патерні master-detail: EntityList (список зліва) + EntityDetailCard (деталі праворуч) + RelationBlock (пов'язані сутності).

**Фази:**
1. Підприємства — список компаній з фільтрами, картка з керівництвом, власниками, фінансами
2. Особи — список осіб з ролями, картка з посадами, контактами, міні-графом зв'язків
3. Фінанси — три підрозділи: Рахунки, Транзакції, Закупівлі

**Статус:** 🟡 в роботі (2026-10-14) — створено EntityList, EntityDetailCard, RelationBlock. Переписано CompaniesView, PeopleView, FinanceView. Додано CSS-стилі.

### ✅ Розподіл інформації по тематичних вкладках (основна ідея)

**Проблема:** результати пошуку потрапляли лише на вкладку «Сутності» та в «Пошук».
Користувач мусив вручну шукати і вставляти інформацію по різних вкладках.

**Рішення:** автоматичний розподіл інформації з пошуку по тематичних вкладках бокового меню.

**Нові вкладки:**

| Вкладка | Що відображає | Джерело даних |
|---------|---------------|---------------|
| **Особи** | Фізичні особи: ПІБ, роль, телефон, email, адреса | `entity_type=person`, `properties.company.director`, `properties.company.contact_person`, `properties.company.founders` |
| **Фінанси** | Фінансова інформація: капітал, податковий статус, КВЕД, контакти | `properties.company.capital`, `properties.company.tax_status`, `properties.company.activities` |
| **Підприємства** | Юридичні особи: повні картки компаній | `entity_type=company`, `properties.company.*` |
| **Гео-мапи** (вже було) | Адреси, координати, зображення місцевості | `properties.geo.*` |
| **Сутності** (вже було) | Усі сутності дослідження | всі `entity_type` |

**Алгоритм розподілу:**
1. Пошук повертає `UniversalEntity[]` → зберігаються в БД (як зараз)
2. Кожна вкладка фільтрує сутності з поточного workspace за своїми критеріями
3. Клік на сутність у вкладці → відкриває детальну картку
4. Нічого не потрібно вручну додавати — все автоматично

**Статус:** ✅ виконано (2026-10-14) — створено `PeopleView.tsx`, `FinanceView.tsx`, `CompaniesView.tsx`, оновлено `Sidebar.tsx`, `Workspace.tsx`, `icons.tsx`
