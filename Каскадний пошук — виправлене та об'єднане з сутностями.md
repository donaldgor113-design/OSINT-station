# Каскадний пошук — виправлене та об'єднане з системою сутностей

Це виправлена й обʼєднана версія ТЗ «Каскадна система пошуку», яка стикує каскад (Tier0–Tier4) з уже затвердженою системою маршрутизації сутностей («Доробка — маршрутизація сутностей»). Два рішення вже зафіксовані і визначають усю архітектуру нижче:

1. **AI-екстракція вбудована прямо в каскад** — не чекає окремої фази. Коли Tier1/Tier2/Tier3 знаходять документи, AI одразу намагається витягти з них структуровані `company`/`person`/`financial_account` + звʼязки — саме так, як і в прикладі декомпозиції з «Доробки».
2. **Зупинка каскаду залежить від повноти структурованих даних**, а не від кількості знайдених посилань — щоб каскад не зупинявся на купі лінків, так і не дійшовши до картки компанії чи особи.

Нижче — лише виправлення й доповнення поверх вихідного ТЗ. Там, де код не змінився (Tier4, конфігурація, базовий `BaseTier`), документ лише посилається на оригінал, а не дублює його.

## 1. Нова модель confidence — `app/search/confidence.py`

**Проблема вихідного ТЗ:** `confidence = min(0.7, 0.15 * len(entities))` рахує кількість знайдених обʼєктів, не їхню цінність. П'ять посилань-«document» давали вищий confidence, ніж одна повна картка компанії.

**Нова логіка:** для кожного `entity_type` визначений набір ключових полів. Confidence — це повнота заповнення цих полів у **найкращій** знайденій сутності очікуваного типу (а не середнє по всіх сутностях — шум не повинен розбавляти хороший збіг).

```python
# app/search/confidence.py
from typing import Any

# Ключові поля для кожного типу сутності. Порожній список (document) —
# означає "сам факт існування не підвищує впевненість", обробляється окремо.
KEY_FIELDS: dict[str, list[str]] = {
    "company": ["edrpou", "name", "address", "status", "director", "owner"],
    "person": ["full_name", "dob", "address", "phone"],
    "financial_account": ["account_number", "owner", "balance"],
    "ip": ["ip", "org", "open_ports", "country"],
    "domain": ["domain", "registrar", "created"],
    "location": ["coordinates", "address"],
}

# document не має "повноти" — кожен додає фіксовану, невелику вагу,
# щоб сама по собі купа посилань ніколи не досягла порогу зупинки
DOCUMENT_WEIGHT = 0.1

# Який entity_type вважається "головним" для кожного наміру пошуку —
# саме його повноту і перевіряє каскад перед зупинкою
PRIMARY_TYPE_BY_INTENT = {
    "company-profile": "company",
    "person-profile": "person",
    "ip-recon": "ip",
    "domain-recon": "domain",
    "geo-context": "location",
    "contact-discovery": "person",
    "social-profile": "person",
    "public-documents": None,   # немає єдиної "головної" сутності
    "media-discovery": None,
    "general-discovery": None,
}


def _entity_completeness(entity: dict[str, Any]) -> float:
    """Частка заповнених ключових полів для однієї сутності (0.0-1.0)."""
    etype = entity.get("entity_type")
    fields = KEY_FIELDS.get(etype)
    if not fields:
        return 0.0

    props = entity.get("properties", {}).get(etype, {})
    # fallback: деякі адаптери кладуть поля прямо в properties без вкладеного ключа
    if not props:
        props = entity.get("properties", {})

    filled = sum(1 for f in fields if props.get(f))
    return filled / len(fields)


def compute_confidence(entities: list[dict[str, Any]], intent: str) -> float:
    """
    Головна зупиняюча метрика каскаду.
    Якщо в намірі немає чіткого "головного" типу (general-discovery тощо) —
    рахуємо м'яко: найповніша сутність будь-якого типу, що має KEY_FIELDS.
    """
    primary = PRIMARY_TYPE_BY_INTENT.get(intent)

    candidates = entities if primary is None else [
        e for e in entities if e.get("entity_type") == primary
    ]
    structured = [e for e in candidates if e.get("entity_type") in KEY_FIELDS]

    best_structured = max((_entity_completeness(e) for e in structured), default=0.0)

    doc_count = sum(1 for e in entities if e.get("entity_type") == "document")
    doc_bonus = min(0.3, doc_count * DOCUMENT_WEIGHT)  # документи — лише бонус, стеля 0.3

    # Структуровані дані завжди важать більше: документи ніколи не
    # дотягують самі по собі до порогу зупинки (0.6 за замовчуванням)
    return min(1.0, best_structured + (doc_bonus if best_structured == 0 else doc_bonus * 0.3))
```

**Наслідок для порогу:** `min_confidence=0.6` тепер означає «у найкращої компанії/особи заповнено \~4 з 6 (або 3 з 4) ключових полів», а не «знайдено 4 посилання». Це узгоджує зупинку каскаду з реальною корисністю результату для вкладок «Підприємства»/«Особи».

## 2. AI-екстракція сутностей — `app/search/entity_extractor.py`

Це новий крок, якого не було у вихідному ТЗ: він перетворює знайдені Tier1/Tier2/Tier3 документи на структуровані сутності одразу в каскаді, а не окремою фазою. Функція параметризована «багатством» тексту — працює і на коротких сніпетах (Tier1), і на повному тексті сторінки (після Tier3).

**Якщо AI-провайдер з основної архітектури (`AIProviderAdapter`, розділ 7 головного документа проєкту) уже реалізований** — викликай його. Якщо ще ні — онач зі мною: або реалізуй мінімальну пряму інтеграцію з Claude API тут (`anthropic` SDK), яку пізніше замінить повноцінний `AIProviderAdapter`, зберігши ту саму сигнатуру функції нижче.

```python
# app/search/entity_extractor.py
import json
import logging
from typing import Any

logger = logging.getLogger(__name__)

EXTRACTION_PROMPT = """
Ти аналізуєш результати пошуку для OSINT-розслідування.
Запит користувача: {query}
Тип запиту: {query_type}

Нижче — знайдені документи (назва, URL, текст). Витягни з них структуровані
сутності, якщо такі дані дійсно присутні в тексті. НЕ вигадуй дані, яких
немає в тексті.

Документи:
{documents}

Поверни JSON-масив сутностей у форматі:
[
  {{
    "entity_type": "company" | "person" | "financial_account" | "location",
    "entity_name": "...",
    "properties": {{ ... поля відповідно до типу ... }},
    "relations": [{{"target_name": "...", "type": "director_of" | "owner_of" | ...}}],
    "source_url": "з якого документа взято",
    "extraction_confidence": 0.0-1.0
  }}
]
Якщо структурованих даних немає — поверни порожній масив [].
"""


async def extract_entities_from_documents(
    ai_provider,
    documents: list[dict[str, Any]],
    query: str,
    query_type: str,
    *,
    max_documents: int = 8,
) -> list[dict[str, Any]]:
    """
    Витягує структуровані сутності (company/person/financial_account/location)
    з уже знайдених document-сутностей. Повертає список у форматі,
    сумісному з UniversalEntity (готовий для декомпозиції і merge).

    Якщо ai_provider недоступний (немає ключа) — повертає [] без помилки,
    каскад просто працює з тим, що вже є.
    """
    if ai_provider is None:
        return []

    available, _ = ai_provider.is_available()
    if not available:
        return []

    docs_for_prompt = documents[:max_documents]
    if not docs_for_prompt:
        return []

    documents_text = "\n\n".join(
        f"[{i}] {d.get('entity_name', '')}\nURL: {d.get('properties', {}).get('document', {}).get('url', '')}\n"
        f"Текст: {_document_text(d)[:3000]}"
        for i, d in enumerate(docs_for_prompt)
    )

    prompt = EXTRACTION_PROMPT.format(
        query=query, query_type=query_type, documents=documents_text
    )

    try:
        raw = await ai_provider.complete(prompt)  # сигнатура AIProviderAdapter
        extracted = json.loads(raw)
    except (json.JSONDecodeError, Exception) as exc:
        logger.warning("Entity extraction failed: %s", exc)
        return []

    return [_to_universal_entity(e) for e in extracted if _is_valid(e)]


def _document_text(doc: dict[str, Any]) -> str:
    d = doc.get("properties", {}).get("document", {})
    return d.get("full_text") or d.get("snippet") or d.get("abstract") or ""


def _is_valid(e: dict[str, Any]) -> bool:
    return bool(e.get("entity_type") and e.get("entity_name"))


def _to_universal_entity(e: dict[str, Any]) -> dict[str, Any]:
    etype = e["entity_type"]
    name = e["entity_name"]
    return {
        "entity_type": etype,
        "entity_id": f"ai_extracted:{etype}:{name.lower()}",
        "entity_name": name,
        "properties": {
            etype: e.get("properties", {}),
            "metadata": {
                "sources": [{
                    "name": "ai_extraction",
                    "confidence": e.get("extraction_confidence", 0.5),
                }],
            },
        },
        "relations": e.get("relations", []),
        "raw_data": {"ai_extraction": {"source_url": e.get("source_url")}},
    }
```

**Важливо:** `entity_id` для AI-екстрагованих сутностей будується за іменем (`ai_extracted:company:тов ромашка»`), а не за ЄДРПОУ/ІПН — AI міг не знайти офіційний ідентифікатор. Це означає, що та сама компанія, знайдена пізніше через Tier0/Tier4 з точним ЄДРПОУ, **не зіллється автоматично** з AI-версією за `_merge_entities` (дедуп за `entity_id`). Тому в Orchestrator (розділ 3) потрібен додатковий крок «м'якого» злиття за збігом `entity_name` — без нього в «Сутностях» зʼявляться дублікати.

## 3. Виправлений Orchestrator — `app/search/orchestrator.py`

**Що виправлено відносно вихідного ТЗ:**

- Додано відсутню `_deep_merge` (без неї падав будь-який повторний `entity_id`)
- `workspace_id` перейменовано на `case_id` — узгоджено з «Доробкою — маршрутизацією сутностей», де вся модель даних (`UniversalEntity`, `relations`) вже будується навколо `case_id`
- Прибрано `Tier3Scraping` із загального циклу `TIERS` — він викликається явно, окремим кроком, а не через уніфікований `tier.search()` (у вихідному ТЗ `Tier3.search()` завжди повертав `skipped=True` і ніколи фактично не викликався — це був мертвий код)
- Після Tier1 і Tier2 додано виклик `extract_entities_from_documents` і м'яке злиття AI-сутностей за `entity_name`
- Confidence тепер рахується **по всьому накопиченому набору сутностей** (`compute_confidence` з розділу 1), а не по одному тіру
- `force_tier` більше не проходить по решті класів марно — явний `break` одразу після виконання потрібного тіра

```python
# app/search/orchestrator.py
import time
import logging
from app.search.detector import detect_query_type, detect_intent
from app.search.confidence import compute_confidence
from app.search.entity_extractor import extract_entities_from_documents
from app.search.tiers.base import TierResult
from app.search.tiers import (
    Tier0Local, Tier1WebSearch, Tier2Dorking, Tier3Scraping, Tier4Specialized,
)

logger = logging.getLogger(__name__)

# Tier3 навмисно відсутній у загальному списку — він enrichment-only
# і викликається явним кроком нижче, а не через уніфікований .search()
TIERS = [Tier0Local, Tier1WebSearch, Tier2Dorking, Tier4Specialized]

# Тіри, після яких має сенс пробувати AI-екстракцію (ті, що повертають
# сирі document-сутності, а не вже структуровані дані)
EXTRACTABLE_TIERS = {"tier1_web", "tier2_dorks"}


class SearchOrchestrator:
    def __init__(self, db_session, ai_provider=None, cache=None):
        self.db = db_session
        self.ai = ai_provider
        self.cache = cache  # спільний кеш-сервіс, розділ 4 — живе довше за один запит
        self._tier_instances = {
            tier_cls: tier_cls(self.db, self.ai, self.cache) for tier_cls in TIERS
        }
        self._tier3 = Tier3Scraping(self.db, self.ai)

    async def search(
        self,
        query: str,
        case_id: int,
        *,
        min_confidence: float = 0.6,
        force_tier: str | None = None,
    ) -> dict:
        query_type = detect_query_type(query)
        intent = detect_intent(query, query_type)

        logger.info(
            "Search start: query=%r type=%s intent=%s case=%s",
            query, query_type, intent, case_id,
        )

        collected: list[TierResult] = []
        final_entities: list[dict] = []

        for tier_cls in TIERS:
            tier = self._tier_instances[tier_cls]

            if force_tier and tier.name != force_tier:
                continue

            available, reason = tier.is_available()
            if not available:
                collected.append(TierResult(tier_name=tier.name, skipped=True, skip_reason=reason))
                logger.info("Tier %s skipped: %s", tier.name, reason)
                continue

            started = time.monotonic()
            try:
                result = await tier.search(query, query_type, case_id)
            except Exception as exc:
                logger.exception("Tier %s failed: %s", tier.name, exc)
                result = TierResult(tier_name=tier.name, error=str(exc))
            result.duration_ms = int((time.monotonic() - started) * 1000)
            collected.append(result)

            final_entities = self._merge_entities(final_entities, result.entities)

            # AI-екстракція одразу поверх свіжих документів цього тіра
            if tier.name in EXTRACTABLE_TIERS and self.ai is not None:
                extracted = await extract_entities_from_documents(
                    self.ai, result.entities, query, query_type,
                )
                final_entities = self._soft_merge_by_name(final_entities, extracted)

            overall_confidence = compute_confidence(final_entities, intent)
            if not force_tier and overall_confidence >= min_confidence and final_entities:
                logger.info("Sufficient after %s (conf=%.2f) — stopping", tier.name, overall_confidence)
                break

            if force_tier and tier.name == force_tier:
                break
        else:
            # Жоден TIERS-тір не дав достатньої впевненості — пробуємо
            # enrichment: беремо топ-N ще не збагачених document-URL
            # і витягуємо повний текст, потім ще раз AI-екстракція
            if not force_tier and self._tier3.is_available()[0]:
                top_urls = self._pick_urls_to_enrich(final_entities)
                if top_urls:
                    started = time.monotonic()
                    enriched_docs = await self._tier3.enrich_urls(top_urls)
                    tier3_result = TierResult(
                        tier_name=self._tier3.name,
                        entities=enriched_docs,
                        duration_ms=int((time.monotonic() - started) * 1000),
                    )
                    collected.append(tier3_result)
                    final_entities = self._merge_entities(final_entities, enriched_docs)

                    if self.ai is not None:
                        extracted = await extract_entities_from_documents(
                            self.ai, enriched_docs, query, query_type,
                        )
                        final_entities = self._soft_merge_by_name(final_entities, extracted)

        return {
            "query": query,
            "query_type": query_type,
            "intent": intent,
            "entities": final_entities,
            "confidence": compute_confidence(final_entities, intent),
            "tiers": [
                {
                    "name": r.tier_name,
                    "entities_count": len(r.entities),
                    "duration_ms": r.duration_ms,
                    "skipped": r.skipped,
                    "skip_reason": r.skip_reason,
                    "error": r.error,
                }
                for r in collected
            ],
            "stopped_at": collected[-1].tier_name if collected else None,
        }

    def _pick_urls_to_enrich(self, entities: list[dict], limit: int = 5) -> list[str]:
        urls = [
            e["properties"]["document"]["url"]
            for e in entities
            if e.get("entity_type") == "document" and e.get("properties", {}).get("document", {}).get("url")
        ]
        return urls[:limit]

    @staticmethod
    def _merge_entities(existing: list[dict], new: list[dict]) -> list[dict]:
        """Дедуплікація за entity_id. Нові дані зливаються в існуючі."""
        by_id = {e["entity_id"]: e for e in existing}
        for e in new:
            eid = e["entity_id"]
            by_id[eid] = _deep_merge(by_id[eid], e) if eid in by_id else e
        return list(by_id.values())

    @staticmethod
    def _soft_merge_by_name(existing: list[dict], new: list[dict]) -> list[dict]:
        """
        Для AI-екстрагованих сутностей: entity_id ненадійний (немає ЄДРПОУ/ІПН),
        тому зливаємо за збігом (entity_type, normalized entity_name).
        """
        def key(e: dict) -> tuple:
            return (e["entity_type"], e["entity_name"].strip().lower())

        by_key = {key(e): e for e in existing}
        for e in new:
            k = key(e)
            by_key[k] = _deep_merge(by_key[k], e) if k in by_key else e
        return list(by_key.values())


def _deep_merge(a: dict, b: dict) -> dict:
    """
    Зливає дві версії однієї сутності: properties — рекурсивно (b доповнює a,
    непорожні значення b мають пріоритет), sources і relations — обʼєднуються
    без дублікатів.
    """
    merged = dict(a)

    merged["properties"] = _deep_merge_dict(
        a.get("properties", {}), b.get("properties", {})
    )

    existing_sources = {
        s["name"]: s for s in a.get("properties", {}).get("metadata", {}).get("sources", [])
    }
    for s in b.get("properties", {}).get("metadata", {}).get("sources", []):
        existing_sources[s["name"]] = s
    merged.setdefault("properties", {}).setdefault("metadata", {})["sources"] = list(existing_sources.values())

    existing_relations = {(r["target_id"], r["type"]) for r in a.get("relations", [])}
    merged_relations = list(a.get("relations", []))
    for r in b.get("relations", []):
        if (r.get("target_id"), r.get("type")) not in existing_relations:
            merged_relations.append(r)
    merged["relations"] = merged_relations

    merged["raw_data"] = {**a.get("raw_data", {}), **b.get("raw_data", {})}
    return merged


def _deep_merge_dict(a: dict, b: dict) -> dict:
    result = dict(a)
    for k, v in b.items():
        if isinstance(v, dict) and isinstance(result.get(k), dict):
            result[k] = _deep_merge_dict(result[k], v)
        elif v:  # непорожнє значення з b перекриває a
            result[k] = v
    return result
```

## 4. Спільний кеш-сервіс — `app/search/cache.py`

**Проблема вихідного ТЗ:** `Tier0Local._cache` жив у `self`, а `tier = tier_cls(self.db, self.ai)` створювався заново на кожен виклик `.search()` — кеш завжди був порожнім. У виправленому Orchestrator (розділ 3) тіри тепер створюються один раз у `__init__`, але якщо `SearchOrchestrator` сам створюється заново на кожен HTTP-запит (як у вихідному роуті) — кеш все одно живе лише один запит. Тому кеш потрібно винести на рівень застосунку, а не тіра чи оркестратора. Redis для цього вже є в технологічному стеку проєкту (Celery + Redis, розділ 8 головного документа) — використовуємо той самий Redis.

```python
# app/search/cache.py
import json
import redis.asyncio as redis


class SearchCache:
    """Тонка обгортка над Redis з TTL. Створюється один раз при старті застосунку."""

    def __init__(self, redis_url: str, ttl_seconds: int = 3600):
        self._redis = redis.from_url(redis_url)
        self._ttl = ttl_seconds

    async def get(self, key: str) -> dict | None:
        raw = await self._redis.get(key)
        return json.loads(raw) if raw else None

    async def set(self, key: str, value: dict) -> None:
        await self._redis.set(key, json.dumps(value), ex=self._ttl)
```

Ініціалізується один раз при старті FastAPI (`app.state.search_cache = SearchCache(settings.REDIS_URL)`), і саме цей інстанс передається в `SearchOrchestrator(db, ai, cache=request.app.state.search_cache)` у роуті — тоді кеш переживає окремі HTTP-запити.

### Виправлений Tier0 — `app/search/tiers/tier0_local.py`

**Виправлено:** `await` для `AsyncSession.execute()`, кеш читається/пишеться через переданий `SearchCache`, а не `self._cache`.

```python
# app/search/tiers/tier0_local.py
from sqlalchemy import select
from app.search.tiers.base import BaseTier, TierResult
from app.models.registry import LegalEntity, IndividualEntrepreneur


class Tier0Local(BaseTier):
    name = "tier0_local"

    def __init__(self, db, ai=None, cache=None):
        self.db = db
        self.cache = cache

    def is_available(self):
        return True, None

    async def search(self, query: str, query_type: str, case_id: int) -> TierResult:
        cache_key = f"tier0:{query_type}:{query.lower()}"
        if self.cache is not None:
            cached = await self.cache.get(cache_key)
            if cached is not None:
                return TierResult(**cached)

        entities = []

        if query_type == "company_edrpou":
            stmt = select(LegalEntity).where(LegalEntity.edrpou == query.strip())
            result = await self.db.execute(stmt)
            row = result.scalar_one_or_none()
            if row:
                entities.append(self._legal_to_entity(row))

        elif query_type == "person_ipn":
            stmt = select(IndividualEntrepreneur).where(
                IndividualEntrepreneur.rnokpp == query.strip()
            )
            result = await self.db.execute(stmt)
            row = result.scalar_one_or_none()
            if row:
                entities.append(self._fop_to_entity(row))

        elif query_type == "text":
            pattern = f"%{query.strip()}%"
            stmt = select(LegalEntity).where(LegalEntity.name.ilike(pattern)).limit(10)
            result = await self.db.execute(stmt)
            for row in result.scalars():
                entities.append(self._legal_to_entity(row))

        tier_result = TierResult(
            tier_name=self.name,
            entities=entities,
            raw_sources=["local_registry"],
        )

        if self.cache is not None:
            await self.cache.set(cache_key, tier_result.__dict__)

        return tier_result

    # _legal_to_entity / _fop_to_entity — без змін відносно вихідного ТЗ
```

**Уточнення щодо `confidence`:** поле `confidence` прибрано з того, що рахує сам Tier0, — тепер зупинку каскаду визначає `compute_confidence()` на рівні Orchestrator (розділ 3), по всьому набору сутностей одразу, а не по одному тіру.

## 9. Критерії приймання

- [ ] Повторний пошук того самого `entity_id` не падає з `NameError` (`_deep_merge` реалізований і протестований)
- [ ] Два послідовні запити з однаковим текстом у межах `ttl_seconds` не б'ють по Tier0/зовнішніх сервісах вдруге — відповідь береться з `SearchCache` (Redis), що живе довше за один HTTP-запит
- [ ] `await self.db.execute(...)` не падає на `AsyncSession` у Tier0
- [ ] Пошук кириличним запитом з пробілом («ТОВ Ромашка») не ламає запит до Jina ні в Tier1, ні в Tier2
- [ ] Пошук за `person_ipn` генерує дорки в Tier2 (раніше тихо пропускався)
- [ ] Після Tier1 (а за потреби й Tier2) у `final_entities` зʼявляються структуровані `company`/`person`-сутності з AI-екстракції, якщо текст документів це дозволяв — не лише `document`-посилання
- [ ] Каскад **не зупиняється** лише на кількості знайдених посилань: сценарій «5 документів, жодної структурованої сутності» дає `confidence < 0.3`, каскад іде далі
- [ ] Каскад **зупиняється**, коли знайдено компанію/особу з заповненими ключовими полями (≥60% за `compute_confidence`), навіть якщо документів знайдено мало
- [ ] `Tier3.enrich_urls()` реально викликається хоча б раз у наскрізному тесті (не є мертвим кодом)
- [ ] AI-екстраговані сутності зливаються з уже наявними за збігом `entity_name`, а не створюють дублікат поруч із сутністю, знайденою через Tier0/Tier4 з точним ЄДРПОУ/ІПН
- [ ] Якщо `ai_provider` недоступний (немає ключа) — каскад працює як і раніше, просто без кроку екстракції, нічого не падає
- [ ] API приймає `case_id`, а не `workspace_id`, і це узгоджено з ендпоінтом `/entities` із «Доробки — маршрутизації сутностей»
